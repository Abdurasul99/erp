## [П1] API открыт наружу без шифрования

`ss -tlnp` показывает `*:3001` — Node слушает **все интерфейсы**, а не localhost.
Проверено снаружи:

```
http://207.180.254.241:3001/api/health           → 200
http://207.180.254.241:3001/api/auth/login       → 401 (эндпоинт отвечает)
http://207.180.254.241:4100/api/health           → 200 (ещё одна служба наружу)
```

Значит, к API можно обращаться **по открытому HTTP, минуя nginx**: пароль при
входе и выданный JWT идут по сети в открытом виде, TLS не применяется, все
ограничения nginx обходятся. Межсетевой экран при этом **выключен**
(`ufw Status: inactive`), то есть порты ничем не прикрыты.

**Исправлено в коде:** `app.listen(PORT, HOST)` с `HOST = process.env.HOST || '127.0.0.1'`.
nginx проксирует на `http://localhost:3001`, поэтому привязка к localhost его не ломает
(проверено по `proxy_pass` в конфиге).

**Осталось на сервере** — включить межсетевой экран:
```bash
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
```
Порядок важен: сначала разрешить 22, иначе включение обрубит SSH.

## [П1] Резервные копии лежат на том же диске, что и база

`/var/backups/wareapp/` на `/dev/sda1` — там же, где PostgreSQL. Выгрузки наружу
нет (проверено: в `wareapp-backup.sh` нет ни `scp`, ни `rsync`, ни `rclone`, ни S3).

Отказ диска или потеря сервера уносит **и базу, и все 31 копию разом**. Для ERP,
в которой лежат деньги клиентов, это единственная точка отказа.

Копия весит 6.1 МБ в сжатом виде — увезти её можно куда угодно, хоть в Telegram.
Минимальный вариант — добавить в конец `wareapp-backup.sh` выгрузку в объектное
хранилище или на второй сервер (тот, что планируется под базу за $170/год).

## [П2] Нет заголовков безопасности

Ответ `https://mywarehouse.uz/` не содержит ни одного из:
`Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`
(или `Content-Security-Policy: frame-ancestors`), `Referrer-Policy`.

В конфиге nginx есть только кэш-заголовки, а `server_tokens off;` **закомментирован** —
поэтому наружу светится `Server: nginx/1.18.0 (Ubuntu)`.

Без `X-Frame-Options` панель можно встроить в чужой iframe (кликджекинг), без HSTS
первый заход по http уязвим к перехвату.

Добавить в серверный блок nginx:
```nginx
server_tokens off;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

Скрипт кладёт файлы в `/root/wareapp/backend/`, а приложение живёт в

перезапуск «прошёл» — а на проде всё осталось прежним. Скрипт нужно поправить или
удалить, чтобы им никто не воспользовался.

положить в репозиторий (делать это вслепую с локальной машины нельзя: версии
могут разойтись).

## [П2] CORS отвечал 500 и спамил алертами

`cors({ origin: cb(new Error(...)) })` бросал ошибку в обработчик express, и
запрос с чужого домена превращался в `500 Internal Server Error`.

Подтверждено на живом сервере: проверочный запрос с чужого Origin **поднял
тревогу в Telegram** — `ALERT: Новые ошибки в логе wareapp-api … Error: CORS:
origin not allowed`. То есть любой бот, постучавшийся с другого домена, шлёт
владельцу ложное уведомление о поломке.

**Исправлено:** отказ отдаётся через `cb(null, false)` — браузер блокирует ответ
сам, сервер отвечает штатно, лог чист.

## Команды, которые остались невыполненными

Авто-режим не пропустил изменение конфигурации прода. Выполнить вручную:

```bash
# 1. Оживить ИИ (без выкладки кода) — резервная копия .env делается первой строкой
ssh root@207.180.254.241
cd /var/www/wareapp/backend
cp -n .env .env.bak-ai-2026-09-17
sed -i '/^AI_/d' .env
cat >> .env <<'EOF'
AI_API_URL=https://clodex.xyz/v1/chat/completions
AI_API_KEY=<ключ>
AI_MODEL=gpt-5.5
AI_FALLBACK_MODELS=gpt-6-astra,gemini-3.8-flash,deepseek-v4.1-flash
EOF
pm2 restart wareapp-api

# 2. Закрыть порты (сначала 22, иначе обрубишь себе SSH)
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable

# 3. Заголовки безопасности — добавить блок из раздела выше, затем
nginx -t && systemctl reload nginx
```

Привязка API к localhost уже сделана в коде и уедет вместе с ближайшей выкладкой
`backend/server.js` — **до неё пункт 2 остаётся единственной защитой порта 3001**.
