# Продукт «Мероприятия» — устройство и выкладка

## Как устроено

```
                    mywarehouse.uz — общая страница входа
                                  │
                       POST /api/auth/login (Wave)
                   токен несёт product: wave | events
                  ┌───────────────┴────────────────┐
           product = wave                    product = events
                  │                                │
   /owner, /admin, /sell …               /events/*  — свой интерфейс
   backend :3001 (pm2 wareapp-api)       events-api :3002 (pm2 events-api)
                  │                                │
       база warehouse — вся Wave          база events — свои таблицы
                  │                                │
                  └──── учётки: companies / users ─┘
                    ведёт только админка WoW; events-api читает
                    лишь столбцы входа под ролью events_identity
```

- **Данные не пересекаются.** У мероприятий своя база `events` и свой процесс.
  К базе Wave сервис подключается ролью, которой выданы права только на столбцы
  входа. Прочитать продажи, кассу, склад или хэши паролей Wave он не может —
  это ограничение базы, проверенное тестом `identity-grants.test.js` на точной
  схеме прода.
- **Вход общий.** Одна страница, один `/api/auth/login`. Продукт компании
  попадает в подписанный токен, по нему интерфейс ведёт в Wave или в
  «Мероприятия».
- **Граница с обеих сторон.** Wave отдаёт учётке мероприятий только `/api/auth/*`,
  всё остальное — 403. Сервис мероприятий не принимает токены Wave.
- **Учётки ведёт только админка WoW.** Продукт выбирается при создании компании
  и дальше не меняется. Роли зависят от продукта; сервер не даст назначить
  кассира в компанию мероприятий и наоборот.

Роли «Мероприятий» (по макету): Учредитель, Руководитель проектов, Координатор,
Декоратор, Флорист, Монтажник.

## Выкладка — по шагам

Сервер `207.180.254.241`, приложение в `/var/www/wareapp`. Команды — из папки
проекта в PowerShell, по одной строке.

**0. Резервная копия базы — обязательно, миграция меняет ограничение ролей.**
```powershell
ssh root@207.180.254.241 'sudo -u postgres pg_dump warehouse | gzip > /var/backups/wareapp/before-events-$(date +%F-%H%M).sql.gz && ls -la /var/backups/wareapp | tail -2'
```
Кавычки здесь одинарные намеренно: в двойных PowerShell выполнил бы
`$(date …)` сам, до отправки на сервер, и имя файла получилось бы битым.
По той же причине в паролях шага 4 не используйте знак `$`.

**1. Код — из КОММИТА, а не из рабочей копии.**

В рабочей копии `backend/server.js` лежат незакоммиченные правки, которые
подключают `backend/recompute.js`, — на сервере этого файла нет, и такой
server.js упал бы на старте. Поэтому выкладываем ровно проверенное
закоммиченное состояние: `git archive` берёт файлы из коммита и собирает их
в один архив.

```powershell
git archive -o wave-deploy.tar HEAD backend/server.js backend/products.js backend/aiClient.js backend/runtime.js backend/companyAccess.js backend/toolsCatalog.js backend/recompute.js events-api/server.js events-api/package.json events-api/package-lock.json events-api/src events-api/sql
```
```powershell
scp wave-deploy.tar root@207.180.254.241:/tmp/
```
```powershell
ssh root@207.180.254.241 "mkdir -p /root/rollback && cp /var/www/wareapp/backend/server.js /root/rollback/server.js.before-events && tar -xf /tmp/wave-deploy.tar -C /var/www/wareapp && cd /var/www/wareapp/backend && ls products.js aiClient.js runtime.js companyAccess.js toolsCatalog.js recompute.js && node --check server.js && echo ГОТОВО"
```
Ждём список шести файлов и `ГОТОВО`. Прежний server.js сохранён в
`/root/rollback/server.js.before-events`.

`node --check` проверяет только синтаксис, отсутствующий модуль он не
заметит. Поэтому список в `git archive` и в `ls` обязан совпадать со всеми
`require('./…')` из `backend/server.js`; проверить локально:
`git show HEAD:backend/server.js | grep -o "require('./[a-zA-Z]*')" | sort -u`.
4 октября в server.js добавился `./recompute`, а в списке его не было —
сервер падал на старте, nginx отдавал 502.

**2. Перезапуск Wave — миграция создаст `companies.product` и расширит роли.**
```powershell
ssh root@207.180.254.241 "pm2 restart wareapp-api && sleep 6 && curl -s localhost:3001/api/health && pm2 logs wareapp-api --lines 40 --nostream | grep -E 'users_role_check|ВНИМАНИЕ'"
```
Ждём `{"status":"ok"}` и строку `users_role_check: добавлены роли …`.
Строк с «ВНИМАНИЕ» быть не должно.

**3. Сервис мероприятий: поставить зависимости** (сами файлы уже распакованы в шаге 1).
```powershell
ssh root@207.180.254.241 "cd /var/www/wareapp/events-api && npm install --omit=dev"
```

**4. База и роли — придумайте два пароля и подставьте.**
```powershell
ssh root@207.180.254.241 "cd /var/www/wareapp/events-api && sudo -u postgres psql -v events_app_pass='ПАРОЛЬ-1' -v events_identity_pass='ПАРОЛЬ-2' -f sql/setup-prod.sql"
```

**5. Настройки сервиса.** Создать `/var/www/wareapp/events-api/.env` по образцу
`.env.example`: `JWT_SECRET` — тот же, что в `backend/.env`; пароли — из шага 4.

**6. Запуск.**
```powershell
ssh root@207.180.254.241 "cd /var/www/wareapp/events-api && pm2 start server.js --name events-api && pm2 save && sleep 3 && curl -s localhost:3002/api/events/health"
```
Ждём `{"status":"ok","service":"events-api"}`.

**7. nginx — адрес сервиса.** В тот же `server { … }`, где уже есть
`location /api/`, добавить блок (nginx выбирает самый длинный подходящий
префикс, так что порядок не важен):
```nginx
location /api/events/ {
    proxy_pass http://localhost:3002/api/events/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```
```powershell
ssh root@207.180.254.241 "nginx -t && systemctl reload nginx"
```

**8. Интерфейс.**
```powershell
cd frontend; npm run build; cd ..
scp -r frontend/dist/* root@207.180.254.241:/var/www/wareapp/frontend/dist/
ssh root@207.180.254.241 "chmod -R a+rX /var/www/wareapp/frontend/dist"
```
`chmod` обязателен — без него nginx отдаст 403 на новые файлы.

**9. Проверка.** В админке WoW → «Компании» → «Добавить» → выбрать продукт
«Мероприятия» → создать учредителя → выйти → войти под ним на общей странице:
должна открыться «Панель руководителя проектов».

### Откат

Wave: `cp /root/rollback/server.js.before-events /var/www/wareapp/backend/server.js`
и `pm2 restart wareapp-api`.
Столбец `companies.product` и расширенный список ролей Wave не мешают — старый
код их просто не читает. Сервис мероприятий: `pm2 delete events-api` и убрать
блок из nginx.

### Сторож

`wareapp-monitor.sh` сейчас следит только за Wave. Чтобы он поднимал и
events-api, в него нужно добавить проверку `http://localhost:3002/api/events/health`.
